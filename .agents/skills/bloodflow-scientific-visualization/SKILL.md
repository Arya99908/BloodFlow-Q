# BloodFlow-Q scientific visualization

Run commands from the repository root. Inspect the current data adapter and chart wrapper before introducing another rendering or statistics implementation.

## Choose the evidence boundary

- `frontend/public/observatory-evidence.json` is generated by `experiments/build_observatory_evidence.py`. Inspect `schema_version`, `methodology`, and `sources` first. Its `observations` retain individual trials, `warm_start` retains the historical paired comparison, `scaling` is a separate supplementary experiment, and `basis_resources` contains separate compilation measurements.
- Observation identity is `id`; compare trials by `family`, `scenario`, and `seed`, keeping `solver`, `status`, `config`, and `source` available to the user. A source locator identifies a JSONL line or JSON run index, not a replacement experiment.
- `runtime_seconds` is seconds; rate fields are fractions; `absolute_gap` is objective points and `relative_gap` is a fraction. Render absent values as unavailable. `feasible` describes the returned solution; `operational_feasible_shot_rate` and `strict_feasible_probability` measure different events.
- Network and allocation graphics use the actual scenario and its validated allocation. Reuse `frontend/src/utils/networkGraph.js` validation. An emergency response has both `original_scenario` and `modified_scenario`; pair each with its corresponding allocation. Position facilities schematically unless measured geographic coordinates exist.

## Chart workflow

1. Select the experiment family, scenarios, solvers and metric before aggregation. Preserve failed, skipped and infeasible counts alongside the plotted valid observations.
2. Use scatter for objective gap versus runtime; identify a Pareto frontier within one comparable scenario/configuration. Use paired segments/differences only for matched seeds. Use box plots plus observed points for repeated trials; a violin is an explicitly descriptive density estimate, never extra evidence. Use scenario-by-solver heatmaps for scenario results and tested-size profiles for scaling.
3. Derive statistics in the shared adapter, not inside tooltip callbacks. Display sample size, units, timing scope and missing counts. For very small samples, foreground the individual values and describe interval limitations.
4. Use zero-based quantity/rate bars and truthful widths. Log runtime axes need real numeric ticks and exclude nonpositive values explicitly. Do not impose minimum visible bar lengths on measured values; give small observations separate focus targets.
5. Use the existing ECharts wrapper for analytical charts and retain the SVG network. Provide accessible text/table equivalents, informative empty states, labelled filters and keyboard-visible selection.
6. Check the rendered result in both themes and narrow layouts. Chart colors follow semantic roles: classical blue, quantum cyan, shortage coral, valid allocation green, constraints amber. Read theme tokens rather than hard-coding a dark-only palette.

## Allocation conservation

For a resource-flow chart, account for original inventory as shipped plus remaining inventory, and requested demand as fulfilled plus unmet. Show only actual compatible shipments. Incompatible possibilities are eligibility exclusions, not rejected shipped units unless the backend records such a measurement. A policy comparison must use identical stock, demand and disruption inputs; compare fulfillment and transport metrics, not objective totals under different policy weights.

Completion means plotted values trace to source rows, filters preserve comparison semantics, and a browser check confirms the same selected values in chart tooltips and the accessible representation.
