## Architecture and data provenance

- `data/*.json` contains fictional banks, hospitals, simplified group compatibility and routes. `backend/data_loader.py`, `data_validation.py`, and `scenario_factory.py` validate/convert these into `optimization/models.py` domain objects. The active bundled scenario is not a live inventory feed.
- `optimization/` holds objective, allocation validation, deterministic greedy, HiGHS MILP/continuous relaxation, bounded exact enumeration, decoder and benchmark adapters. All genuine metrics should derive from returned solver records and independent validation.
- `quantum/qubo.py` constructs bounded binary shipment/unmet/slack registers and equality penalties; `ising.py` converts the energy; `qaoa_solver.py` optimizes ideal statevector expectation and samples a final Aer circuit. Warm preparation is LP-derived with validated greedy/uniform fallbacks. The implemented XY exchanges preserve excitation count, not all allocation equations.
- `backend/services.py` is the orchestration boundary. `backend/schemas.py` validates incoming payloads. FastAPI routers forward scenario, optimization, emergency, benchmark and demo requests. `/results` is process-local memory, not durable/shared storage. The `/chat` route is a rules-based domain responder; it neither calls an external LLM nor runs an optimizer on a chat request.
- `emergency/` modifies a scenario through demand/inventory/route/priority events, then evaluates before/after allocations. A demand-spike result is not a prediction of real blood demand.
- `frontend/src/navigation.js` supplies all 16 visible destinations; `App.jsx` handles history, lazy pages, quick optimization and synthetic coordination state. `services/api.js` is the common HTTP boundary. `useApi` supplies loading/error/reload state. The integration workstream added `createLatestRequest` arbitration and invalidation on cleanup so stale requests cannot overwrite newer data or post unmount state updates.
- `frontend/public/quantum-value-study.json`, `warm-qaoa-paired-20261022.json`, and `quantum-followup-study.json` are independent saved studies. The report pages do not execute those experiments on load. `scripts/export-research-followup.py` reads recorded analyses and exports a summary; it does not invent measurements.
- `research/quantum_experiments/` contains isolated reduced encodings, CVaR, feasible-subspace mixers, transfer, noise, scaling, and quantum-component replacement research. Its enumerated tables/state preparation costs are separate from production allocation and must remain visible in scientific accounting.
- Private donor/request operations use browser Supabase Auth, RLS-protected tables, and named RPCs from `services/donorNetwork.js`. They are distinct from FastAPI's deterministic synthetic coordination walkthrough. No email/SMS provider or actual donor contact is configured by the synthetic walkthrough.

Dependencies at baseline: React/Vite frontend with checked-in `frontend/package-lock.json`; Python FastAPI/Pydantic, SciPy, Qiskit/Aer and uvicorn declared in `requirements.txt` and `requirements-prod.txt`. Python requirements use ranges rather than a complete environment lock, and NumPy arrives transitively. Reports must capture actual installed versions; these requirement files alone do not reproduce a historical numerical environment. Production Vite builds require an explicit HTTPS API origin; FastAPI production configuration requires exact HTTPS CORS origins and suppresses debug/OpenAPI routes.

No `AGENTS.md` was present in the audited repository outside dependencies. README/startup/deployment docs exist. At baseline, `docs/STARTUP.md` described a different Desktop path and incorrectly said this folder had no Git metadata; it now uses a portable checkout path and correctly identifies the audited Git branch. No `.github/` directory or GitHub Actions workflow exists at the baseline. Hosting configuration is not a substitute for test CI.

## Findings, changes and remaining limits

1. **Fixed in this workstream:** clipboard writes could report success when the API was unavailable or rejected permission; now errors are explicit and success waits for resolution. Missing benchmark metrics could be graphed as measured zero through `Number(null)`; now absent/invalid values are excluded while real zero remains. Tests: `node --test frontend/tests/measurementValues.test.js` — 3 passed.
2. **Test completeness:** nine pytest methods were absent from unittest counts; final verification must use the full available discovery method. No test is disabled to conceal this.
3. **Scientific baseline:** branch availability is not algorithmic merit. The target's bounded-register mapping and provenance are preferable to the older branch, but current LP seeds frequently already solve the tiny classical allocation problem; no branch supports an unqualified quantum-advantage claim.
4. **Historical evidence:** earlier reports and generated hashes remain historical. A report's claim that a checkout lacked Git metadata does not describe today's repository. Newly measured runtimes must come from current recorded runs, not copied historical tables.
5. **Private service limitation:** unauthenticated local public API checks cannot verify private Supabase writes, RLS deployment, notifications, or medical operations. Those paths remain explicitly blocked for end-to-end verification.
6. **Browser limitation:** all 16 routes served the app shell; this audit did not equate that with rendered interaction correctness. Current browser availability and the Network workstream's direct checks are documented separately. If browser access remains unavailable, visual layout, console behavior and real pointer/keyboard actions must remain marked unverified.
7. **Reproducibility:** Python ranges and cross-platform optimizer trajectories mean identical source/settings need not produce identical historical histograms; the earlier same-environment comparison matched 120/120 implementation pairs but only 97/120 historical Windows histograms. Those are historical integration results, not new performance measurements in this audit.
8. **Maintainability:** production and isolated research intentionally have different representations; avoid creating another subtly divergent production QAOA class. Source helper extraction should consolidate validation and metadata while retaining independently implemented mathematical checks.
9. **Navigation/data consistency:** no indiscriminate branch merge is warranted. Keep explicit frontend penalty semantics, preserve working navigation/stale-result repairs, and expose unsupported simulation sizes as refusals instead of fabricated outputs.

Final implementation changes, measured benchmark coverage, and complete build/test outcomes belong to the updated experiments and Network reports.
