## Unsupported and explicitly unmeasured combinations

- The application supports continuous choices of objective/penalty weights and numerical parameters; an infinite Cartesian product is not a finite scenario inventory. The frozen choices above are reported with their domain limits. New weights/instances need new experiments.
- Full222-qubit statevector simulation exceeds both this14-qubit benchmark cap and production16-qubit guard. No fabricated large-instance QAOA runtime or hardware extrapolation is supplied.
- Production gate-noise/backend selection is not implemented. Noisy measurements belong to isolated supplementary circuits only. Real hardware access is unavailable; all quantum execution here is simulated.
- XY preserves only the register-specific invariant established by encoding/initial-state tests; it is not a blanket guarantee of allocation constraints. `feasible_shot_rate` concerns decoded allocation/shortage feasibility; `final_feasible_probability` and `optimal_shot_rate` use the stricter encoded equality proof mask. Keep these metrics distinct.
- Emergency UI offers demand spike, inventory reduction, route disruption and priority shift. Fresh benchmark enumerates concrete compact demand/disruption plus shortage cases. Arbitrary inventory reductions and priority shifts have regression/API coverage, not a full fresh stochastic performance sweep. Malformed/over-reduction requests are validation tests, not solver runs.
- Private Supabase/RLS workflows require an authenticated configured environment; they are UI/authorization verification, not optimization benchmarks. They remain blocked for live end-to-end checks.
- Single pilot, CLI smoke, invariant test, chart render or successful HTTP response is not a full benchmark. Historical seed/settings results are not pooled with current measurements.

## Regenerate summaries

```sh
python -m experiments.analyze_full_review --input experiments/results/full_review_20261024/production_v2
```

This reads only durable rows and produces summary.json, scenario_method_summary.csv, primary_method_summary.csv, and full-review-study.json. It records raw SHA256 and whether complete.json exists; duplicate keys are rejected. Every metric records its own finite-observation n, mean, median and sample standard deviation(n−1; null below2 observations). Missing metrics remain missing, never zero. Feasibility is returned-solution feasibility, distinct from shot rates. Primary aggregate rows exclude historical/demo/boundary/full datasets; ablations still have fewer scenarios and must be compared within matched cases. Public-panel means use completed rows only; global failure/skip counts remain visible. The analyzer does not complete pending runs or repair failures.
